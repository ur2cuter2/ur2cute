# 漢字でGO！ 運用取扱説明

## 1. アプリ概要

漢字でGO！は、小学生向けの漢字書き取り反復練習アプリです。

塾の漢字テスト、模試、家庭学習などで間違えた問題だけを登録し、忘れやすい漢字をくり返し練習するために使います。1問ごとに制限時間があり、標準では60秒です。iPadでは通常の文字入力欄に、iPadの手書き入力機能を使って答えを入力します。

このアプリは入試本番や紙テストの完全再現ではなく、反復練習用です。候補表示や入力補助に頼りすぎていないかは、紙テストモードで本当に書けるか確認します。

## 2. ファイル構成

```text
kanji-de-go/
  index.html
  style.css
  app.js
  kanji-mistakes.csv
  data/
    kanji_mistakes.json
```

- `index.html`: アプリ本体のHTMLです。ブラウザで開く入口です。
- `style.css`: 画面デザイン、道路風レーン、読みの接近演出、正解演出などのCSSです。
- `app.js`: ゲーム進行、CSV読込、localStorage保存、紙テスト、データ管理を担当します。
- `kanji-mistakes.csv`: 問題マスタの正本です。正式運用ではここに問題を追加します。
- `data/kanji_mistakes.json`: 初期実装時のサンプルJSONです。現在の主運用ではCSVを正本にします。

## 3. データ運用方針

漢字でGO！では、データを次のように分けて扱います。

- 問題マスタ: `kanji-mistakes.csv`
- 学習進捗: ブラウザの `localStorage`
- バックアップ: 短縮JSON

問題文、読み、答え、意味、出典、誤答、間違い分類などのマスタ情報はCSVで管理します。`review_stage`、`correct_streak`、`miss_count`、`next_review_date`、`status` などの進捗情報はCSVに入れません。これらはアプリがlocalStorageに保存します。

CSVの問題文や意味を修正しても、同じ `id` であれば学習進捗は保持されます。

## 4. CSV仕様

正式CSVヘッダーは次の形です。

```csv
id,source_date,source_type,sentence,reading,answer,acceptable_answers,meaning,wrong_answer,mistake_type,time_limit_sec
```

各列の説明:

- `id`: 問題IDです。例: `kanji_001`
- `source_date`: 出題日または登録日です。例: `2026-06-20` または `2026/6/20`
- `source_type`: 出典です。例: `5年前期5回漢字テスト②`
- `sentence`: 問題文です。
- `reading`: 下線部や書き取り対象の読みです。
- `answer`: 正解です。
- `acceptable_answers`: 許容解です。通常は正解と同じで構いません。複数ある場合はカンマまたは読点で区切ります。
- `meaning`: 意味です。必須です。
- `wrong_answer`: 本人の誤答です。空欄可です。
- `mistake_type`: 間違い分類です。例: `同音異字`、`未記入`。空欄可です。
- `time_limit_sec`: 制限時間です。空欄なら60秒になります。

必須項目:

- `id`
- `source_date`
- `source_type`
- `sentence`
- `reading`
- `answer`
- `meaning`

特に `meaning` は必須です。空欄の行は読み込まれず、何行目が空欄かエラー表示されます。

CSVには次の進捗管理列を入れません。

```text
review_stage,correct_streak,miss_count,next_review_date,status
```

## 5. ID採番ルール

IDは `kanji_001` の形式で、3桁ゼロ埋めにします。

次に問題を追加するときは、既存最大IDの次から採番します。現在の `kanji-mistakes.csv` は `kanji_001` から `kanji_007` まで使っているため、次回作成時は `kanji_008` から開始する想定です。

同じIDがCSV内に重複していると読み込みエラーになります。既存localStorageに同じIDがある場合は、同じ問題として扱われ、マスタ項目だけ更新されます。

## 6. 問題追加フロー

1. 漢字テスト画像をChatGPTプロジェクトにアップロードします。
2. ChatGPTに、不正解問題だけを正式CSVレコード化してもらいます。
3. CSVの内容を確認します。
4. `kanji-mistakes.csv` に追記します。
5. アプリのデータ管理画面で、次のどちらかを行います。
   - CSV貼り付けインポートにCSV全体または追加分を貼り付ける
   - HTTP配信している場合はCSV自動読込またはCSVから修復を使う
   - HTMLを直接開いている場合は「CSVファイルを選んで修復」を使う
6. ホーム画面で今日の対象問題数を確認します。
7. 今日の練習または紙テストモードに新しい問題が出ることを確認します。

CSVを貼り付ける場合も、必ず正式ヘッダー行を含めてください。

## 7. 紙テスト併用フロー

ゲーム画面は反復練習用です。iPadの手書き入力は便利ですが、候補表示や変換補助で答えに近づけてしまうことがあります。

週末、ミニテスト前、模試前などには紙テストモードを使います。紙テストモードでは、問題一覧を見て紙に実際に書き、必要に応じて答え一覧を表示して確認します。

目安:

- 平日: ゲームで反復練習
- 週末: 紙テストモードで本当に書けるか確認
- テスト前: 間違えた問題だけ再度ゲームと紙で確認

## 8. バックアップ

バックアップには短縮JSONを使います。

短縮JSONには、問題文、読み、答え、意味などの問題マスタ情報は含めません。保存されるのはユーザー名と学習進捗だけです。

例:

```json
{"v":1,"u":"ユーザー名","p":{"kanji_001":[1,1,1,"2026-06-21",0]}}
```

短縮JSONはiPadでコピーしやすいよう、改行なし、短縮キーで出力されます。

- `v`: バックアップ形式バージョン
- `u`: ユーザー名
- `p`: 問題IDごとの進捗

問題マスタはCSVが正本です。バックアップJSONだけでは問題文や答えは復元できません。新しい端末で復元するときは、先にCSVを読み込んでから短縮JSONをインポートします。

## 9. トラブルシューティング

### CSVが読み込めない

HTMLを直接開いている場合、ブラウザの制限で `kanji-mistakes.csv` を自動fetchできないことがあります。その場合はデータ管理画面で「CSVファイルを選んで修復」を使うか、CSV貼り付けインポートを使ってください。

HTTP配信している場合は、`index.html` と同じ階層に `kanji-mistakes.csv` があるか確認します。代替パスとして `data/kanji-mistakes.csv` も読み込み対象です。

### 文字化けする

CSVはUTF-8で保存してください。Excelなどで編集した場合、保存形式によって文字化けすることがあります。文字化けした場合は、UTF-8のCSVとして保存し直してください。

### 今日の問題が出ない

出題対象になる条件は次の通りです。

- `status` が `active`
- `next_review_date` が今日以前

正解が続いた問題は次回復習日が先になったり、卒業扱いになったりします。データ管理画面で全データ初期化をすると進捗も消えますが、通常はバックアップを取ってから行ってください。

### localStorageを初期化したい

データ管理画面に初期化機能があります。

- 学習データをサンプルに戻す: ユーザー名は残ります。
- 全データを初期化: ユーザー名も消え、初回入力画面に戻ります。

正式運用では、初期化前に短縮JSONバックアップを取ってください。

### iPadで入力しづらい

入力欄をタップしてから、iPadの手書き入力を使います。入力候補が強く出る場合があります。ゲームは反復練習として使い、本当に書けるかは紙テストモードで確認してください。

### CSV貼り付けインポートとCSV自動読込の違い

CSV自動読込は、アプリ起動時または「CSVから修復」で `kanji-mistakes.csv` をブラウザがfetchする方法です。HTTP配信では便利ですが、HTMLを直接開いた場合は失敗することがあります。

CSV貼り付けインポートは、textareaに貼り付けたCSVだけを読み込みます。外部CSVファイルのfetchに失敗していても使えます。

「CSVファイルを選んで修復」は、HTMLを直接開いている場合でも、手元のCSVファイルを選んで読み込める方法です。

## 10. 注意事項

- 既存ゲームのUIやロゴをコピーしないでください。
- 個人名をコードにハードコードしないでください。ユーザー名は初回入力またはデータ管理画面で変更します。
- GitHubへのコミット、プッシュ、PR作成はCodexにさせないでください。
- 問題マスタはCSV、進捗はlocalStorage、バックアップは短縮JSONという役割分担を崩さないでください。

## テストモード

`test.html` を開くとテストモードで起動します。URL に `?mode=test` を付けて `index.html?mode=test` のように開いた場合もテストモードになります。

テストモードでは、本番と同じ `kanji-mistakes.csv`（代替として `data/kanji-mistakes.csv`）を読み込みますが、プレイ結果、ユーザー名、進捗、復習ステージ、正解・不正解ログ、リトライ状態は本番の `localStorage` に保存されません。画面表示中だけメモリ上で状態を持つため、リロードするとテスト中の履歴は消えます。

iPadでの表示確認、手書き入力確認、CSV読込確認、正解・不正解表示、タイマーや画面遷移の確認に使います。本番学習は通常どおり `index.html` を使います。

テストモード中のデータ管理画面では、本番データを変更する可能性があるバックアップ書き出し、バックアップインポート、ユーザー名変更、学習データ初期化、全データ初期化は無効になります。CSVから修復、CSVファイル選択、CSV貼り付けインポートはテスト中のメモリにだけ反映されます。

## 公開環境への同期

開発はローカル環境 `C:\apps\ur2cute\kanji-de-go` で行います。

iPadから確認する公開環境へ反映する場合は、ローカル専用フォルダ `scripts_local/` に置いた `sync_to_public.bat` をダブルクリックします。

このbatは `sync_to_public.ps1` を呼び出し、必要ファイルを以下へコピーします。

`C:\apps\ur2cuter_public\ur2cute\kanji-de-go`

`scripts_local/` は個人PC依存の絶対パスを含むため、Git管理対象外です。Codexには原則としてローカル開発環境のみを編集させ、公開環境への反映はこの同期スクリプトで行います。
